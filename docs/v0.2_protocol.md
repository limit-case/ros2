# v0.2 confirmation protocol (DRAFT, not run, needs owner approval)

Purpose: get one clean held-out number for the RGB-proposal method. The D435 and D415 test sets of ClearGrasp have
been seen (2026-11-12): the setting selected on val overfit, and preferring the untuned setting is a test-informed
choice. So ClearGrasp test can no longer confirm anything. TransCG D435 has not been touched by this package.

## 1. Frozen before the run (no changes after this is approved)

| Item | Value |
|---|---|
| Method | `scripts/eval_rgb_proposal.py` at the approved commit: one ring per connected region of the predicted mask |
| `ring_px` | 15 |
| `min_basin_depth_m` / `min_basin_depth_rel` | 0.01 / 0.015 (the v0.1 values in `config/realsense_d435.yaml`) |
| `min_ring_px` | 20 |
| Mask network | ClearGrasp `mask_segmentation/checkpoint_mask.pth`, sha256 `e8d36e4b...ff1863`, 256x256 nearest resize, argmax, RGB only |
| Baseline, same images | v0.1 depth-only `filter_cli` with `config/realsense_d435.yaml` |
| Metric | `bucket_counts` / `summarize` of `scripts/eval_glassbench.py`, tolerance 5% of ground truth, TransCG's own mask and ground-truth depth, pooled pixels |

## 2. Data

- TransCG, D435 camera only (`depth1*.png`, `rgb1.png` through GlassBench `loader.load_transcg(view, "D435")`).
- All D435 views that have ground truth, or, if that is too slow, a fixed random sample drawn with a seed written
  here before the run (GlassBench used seed 0, 300 views; a different seed avoids reusing a subset already studied).
  Owner picks one of the two before the run.
- No tuning, no subset selection after seeing results, no reruns except for a crash (then the same command again).

## 3. Run, once

1. Only code change allowed beforehand: add a TransCG loader path to `eval_rgb_proposal.py` and
   `eval_glassbench.py` (no change to `ring_flag`, thresholds or metric code). Commit it, pass CI, then freeze.
2. Generate masks into `out/rgb_masks/transcg-d435/` (gitignored).
3. Run the frozen RGB setting and the v0.1 baseline once each. Write **everything** to `out/transcg/` (gitignored);
   afterwards only the pooled summary rows may be copied to `results/` (section 5).

## 4. Declared before the run: what counts as confirmed

- Primary: wrong removed (RGB) is higher than wrong removed (v0.1) on the same images, with outside-mask flagged
  below v0.1's.
- Reported whatever happens: wrong among returned (raw -> after), wrong removed, correct lost, outside-mask flagged,
  mask IoU and area vs ground truth, wrong pixels inside the proposal, share of missing pixels.
- If the primary criterion fails, v0.2 reports that and the method is not shipped as the default.

Known threats, stated up front: the mask network never saw TransCG (other objects, other backgrounds), so mask
quality may dominate; TransCG scenes are cluttered tabletop scenes, still not doors or windows; ground truth comes
from object models and tracked poses, not from opaque twins.

Owner decision, 2026-11-12:

  numbers, no pixels), always with this attribution and licence line next to them:

  > Evaluated on [TransCG](https://graspnet.net/transcg): Fang, H., Fang, H.-S., Xu, S., Lu, C. "TransCG: A Large-Scale Real-World Dataset for Transparent Object Depth Completion and a Grasping Baseline." IEEE RA-L 7(3):7383-7390, 2022. doi:10.1109/LRA.2022.3183256
  > Licensed CC BY-NC-SA 4.0 (Creative Commons Attribution-NonCommercial-ShareAlike 4.0 International),
  > non-commercial. No TransCG data is redistributed here.

  Licence version checked on 2026-11-12: the TransCG repository (README and LICENSE file,
  github.com/Galaxies99/TransCG) says "Creative Commons Attribution-NonCommercial-ShareAlike 4.0 International"; the
  dataset page (graspnet.net/transcg) says "Creative Commons Attribution 4.0 Non Commercial License (BY-NC-SA)".
  GlassBench already publishes TransCG-derived numbers this way.
- **Never committed or shipped**: TransCG images, per-image data, per-image CSVs, masks (ground truth or predicted),
  point clouds, bags, sidecars, previews, or anything else rendered from TransCG.
- In practice: the run writes everything to `out/transcg/` (gitignored). Only the one-row pooled summary
  (`*_summary.csv`, no image ids) may be copied into `results/`; the per-image `eval_<name>.csv` and the `.md` stay in
  `out/`. The eval scripts must write to `--out out/transcg`, not to `results/`.
- Check before every commit and release: `git status --short` shows nothing under `out/`; no TransCG view id appears
  in any tracked file; the release asset is `demo_bag/` only (ClearGrasp, see `NOTICE`).
